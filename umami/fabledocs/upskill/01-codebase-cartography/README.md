# 01 — Codebase Cartography

Maps before territory. This module gives you the shape of Umami before you dive into any one part, so later modules have somewhere to hang their detail.

Read in this order:

1. [`01-system-map.md`](01-system-map.md) — the repo's overall shape, ownership map, public vs. private surfaces.
2. [`02-file-reading-order.md`](02-file-reading-order.md) — 30 files in a deliberate order, with junior/mid/senior paths.
3. [`03-domain-glossary.md`](03-domain-glossary.md) — the product/domain nouns and where each lives in code.
4. [`04-runtime-and-tooling-map.md`](04-runtime-and-tooling-map.md) — package manager, build, test, runtime boundaries, env vars.
5. [`05-key-flows.md`](05-key-flows.md) — **the centerpiece**: six flows traced end to end. Everything else references these.

If you only read one file in this module, read `05-key-flows.md`. If you're brand new, read them in order.
